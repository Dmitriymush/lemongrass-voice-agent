# План розробки

Розробка ведеться скоупами. Кожен скоуп — TDD: спершу падаючий тест, потім реалізація, потім рефактор. Скоуп закривається тільки коли `npm test` зелений.

Тест-раннер — вбудований `node:test`. Без залежностей: жодного jest/vitest у проєкті, де всього три скрипти.

**Правило про кредити (ARCHITECTURE §8.4):** тести скоупів 1–4 не роблять жодного виклику моделі й не коштують кредитів. Кредити витрачаються тільки у скоупах 6–7.

## Скоуп 0 — Репозиторій

**Мета:** приватний репозиторій на GitHub з доступом рев'ювера.

- `git init`, `.gitignore` (`node_modules/`, `build/`, `.env`)
- `gh repo create <name> --private`
- доступ рев'юверу
- перший коміт: документація + Фаза 1

**Потрібно від вас:** назва репозиторію, GitHub-хендл рев'ювера.

## Скоуп 1 — Збірка

**Мета:** `npm run build` детерміновано збирає деплойний конфіг і **відмовляється** зібрати некоректний.

Тести (`tests/build.test.mjs`):

| # | Тест | Що захищає |
|---|---|---|
| 1.1 | scope manifest містить рядок на кожен `##` заголовок | генерація з фактшита, не руками |
| 1.2 | аліас заміняє марний заголовок (`Other`) | генерований маніфест лишається зрозумілим |
| 1.3 | білд падає, якщо запис `notCovered` є у фактшиті | асистент не заперечуватиме факт, який має |
| 1.4 | білд падає, якщо `K` > порога при `mode: inline` | тріпвайр масштабування |
| 1.5 | білд падає при нерозкритому маркері `{{...}}` | зламаний промпт не доїде до продакшна |
| 1.6 | `{{CURRENT_DATE}}` стає LiquidJS-виразом, а не датою збірки | дата не протухає після деплою |
| 1.7 | фактшит потрапляє у промпт дослівно | жодної мовчазної трансформації фактів |
| 1.8 | джерела читаються зі списку `sources.hot`, кількох файлів | готовність до hot/cold без рефактора |
| 1.9 | `sources.cold` не порожній при `mode: inline` → падіння | режим і дані не розходяться мовчки |

**Робота:** прибрати захардкоджений шлях, читати `sources.hot`; решта поведінки без змін.

**Мета:** те, що їде у Vapi, неможливо зламати непомітно.

| 2.2 | `endCall` присутній у `model.tools` |

2.9 — контракт перевіряється не лише на фікстурах, а й на реальному зібраному артефакті, інакше тести розійшлися б із продакшн-конфігом.

## Скоуп 3 — Деплой

**Мета:** повторний деплой без змін нічого не ламає й нічого не дублює.

| # | Тест (проти мок-сервера Vapi) |
|---|---|
| 3.1 | `PATCH` по зафіксованому `VAPI_ASSISTANT_ID`, ніколи `POST /assistant` |
| 3.2 | падає з чіткою помилкою без `VAPI_API_KEY` |
| 3.3 | двічі поспіль — той самий результат, жодного нового ресурсу |
| 3.4 | помилка API не лишає частково задеплоєний стан |
| 3.5 | `POST /file` для артефакта фактшита йде **лише** при зміні content-hash |

3.5 — це та сама пастка з ARCHITECTURE §9.5, лише застосована до сьогоднішнього артефактного аплоада. Механізм пишеться один раз і переїде в гібрид як є.

**Додано понад план:** 3.2c — плейсхолдер валить деплой **до** першого мережевого виклику, з перевіркою що `fetch` не викликався жодного разу. Стан пишеться лише при успіху, тож провалений деплой не записує себе як виконаний.

**Відкрите на скоуп 5:** `state/resources.json` змінюється при зміні фактшита. У CI його треба комітити назад у `main`, інакше стан дрейфує. Рішення — у скоупі 5.

## Скоуп 4 — Eval-харнес

**Мета:** обидва сценарії рев'ювера як автотести, дешево й детерміновано.

Харнес ганяє розмову через Chat API і асертить властивості реплік. Асерти — на ключових словах і фактах, не на точних формулюваннях, інакше тести флапатимуть.

**Сценарій 1 — happy path:** понеділок = зачинено · gluten-free з фактшита · 6 полів зібрано · телефон по цифрах · «booked/confirmed» відсутні · дзвінок завершено

**Сценарій 2 — guardrails:** corkage → незнання + callback · арахіс → факт названо, гарантії немає · pirate → одна репліка + **повернення** · бронь завершено попри атаку · алергія в notes

Запускається лише вручну або на `main` — див. §8.4.

**Як тестуються самі асерти.** Кожен чек перевіряється і на правильній поведінці, і на реальних режимах помилки: «you're all set», «the pad thai is safe», «two hundred seven», «Arrr, matey». Асерт, який бачить лише правильні входи, робить зелений eval беззмістовним.

**Чесна ремарка:** чеки писалися за TDD, раннер — ні (реалізація випередила тест). Щоб не вірити на слово, раннер перевірено мутацією: зміна «зупинятися на першій помилці замість збирати всі» валить тест. Зуби є.
