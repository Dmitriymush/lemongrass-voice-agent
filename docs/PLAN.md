## Скоуп 6 — Поділ HOT/COLD

**Мета:** `kb-fact-sheet.md` лишається недоторканим, поділ — детермінований артефакт збірки.

Нове: `kb/routing.json` — які секції HOT, які COLD, правило витягування алергенів.

| # | Тест | Що захищає |
|---|---|---|
| 6.1 | секції `hot` потрапляють у промпт, `cold` — ні | межа реальна, а не декларативна |
| 6.2 | COLD пишеться окремим артефактом для аплоаду | те, що їде в KB, детерміноване |
| 6.3 | рядки `Contains …` із COLD витягуються в алергенну матрицю HOT | ARCHITECTURE §4.3 |
| 6.4 | витягування **дослівне**, без зміни тексту й ціни | жодної трансформації фактів |
| 6.5 | секція, якої немає в `routing.json`, валить збірку | новий розділ фактшита не зникне мовчки |
| 6.6 | scope manifest містить теми **обох** частин | інакше COLD-питання відбивались би як «не покрито» |
| 6.7 | `K_hot` > порога → збірка падає | тріпвайр, тепер на HOT-ядрі |
| 6.8 | контрольоване дублювання: у HOT і COLD одночасно лише алергенні рядки | випадкове дублювання ловиться |

## Скоуп 7 — Query tool і порядок деплою

**Мета:** COLD доїжджає у Vapi, асистент уміє його питати, повторний деплой нічого не дублює.

| # | Тест |
|---|---|
| 7.1 | `model.tools` містить `endCall` **і** `query` |
| 7.2 | `query.knowledgeBases[0].fileIds` не порожній |
| 7.3 | `query` має `requestStartMessage` — гість не чує тиші під час пошуку |
| 7.4 | порядок деплою: `POST /file` → `PATCH /tool` → `PATCH /assistant` |
| 7.5 | патч асистента не йде, якщо оновлення інструмента впало |
| 7.6 | COLD не змінився → жодного `POST /file`, `fileId` зберігається |
| 7.7 | `toolId` тримається у `state/resources.json`, інструмент не створюється двічі |

**Спрощено після емпіричної перевірки:** Vapi приймає `query` tool **інлайном** у `model.tools`, окремий ресурс і `toolIds` не потрібні. Трикроковий порядок звівся до двокрокового `file → assistant`, разом із ним зник цілий клас відмов.

**Дві знахідки, яких у плані не було, бо їх не можна було передбачити з доків:**

- **7.8** Vapi **не обробляє `text/markdown`** — файл отримує `status: failed` без пояснень, а байт-ідентичний `text/plain` проходить. Деплой тепер чекає на статус і падає з поясненням замість того, щоб лишити асистента з базою, яка мовчки нічого не повертає.
- **7.9–7.10** `PATCH` — часткове оновлення: поле, прибране з репозиторію, лишається на асистенті назавжди. `endCallPhrases` пережив своє видалення. Виправлено явним зануленням плюс **read-after-write**: після деплою асистент читається назад і проганяється через той самий контракт. Обіцянка «git — джерело правди» тепер перевіряється, а не декларується.

## Скоуп 8 — Холодний кейс в eval

**Мета:** довести, що пошук справді викликається, а не тихо ігнорується.

Відомий режим відмови: компактна модель не кличе query tool, у логах немає tool call, а відповідь виглядає правдоподібно. Без цього тесту гібрид міг би бути «підключений і непрацюючий».

| # | Тест |
|---|---|
| 8.1 | питання про ціну конкретної страви → відповідь містить число з фактшита |
| 8.2 | питання про страву, якої в меню немає → визнання незнання, не вигадка |
| 8.3 | алергенне питання відповідається **без** виклику пошуку |
